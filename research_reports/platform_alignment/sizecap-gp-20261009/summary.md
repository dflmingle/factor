# 方向 1：无 size 净额天花板（2026-10-09，零平台算力）

**一句话**：把目标函数修成"平台真实排序口径 + `|corr_size| ≤ 0.30` 硬门槛"后，374 字段全空间搜出的
天花板 = **+4.46%/年**（可提交形态）；而现役池是 **23.8%/年**。**不是搜索范围不够。**

## 一、结论

1. **可提交形态的天花板 = +4.46%/年**（`|corr_size| ≤ 0.30` 且换手 ≤ 0.30，120 信号日，成本 0.30% 单边已扣）
   —— **现役池（23.8%/年）的 1/5**。
2. 放宽换手到 0.60，最好 +6.45%/年（换手 **0.433**、毛 +13.0%）——池换手会直接爆掉 0.30 约束，**不可提交**。
3. **而且这个"最好"不是新信息**：双重约束档前 5 名全是 `Inv(low)` / `Inv(hma3)` / `Inv(wma3)` /
   `Inv(ema5)` / `Inv(vma10)`——**低价股（价格水平）因子**，与 size 秩相关 0.21，是 size 的**近亲**。
   ⇒ 把 size 相关压到 0.30 以下后，GP 找到的最优方向仍然是"更便宜的股票"。
4. **分布**：`|corr_size| ≤ 0.30` 档 **983 条**记录，中位净额 **−10.1%**，仅 **6%** 为正。
5. **对照（不加约束）**：最好 +15.03%（换手 0.086，`Inv(Ref(ratio_a_share_mv,20))`，corr = **−0.992**）、
   +12.36%（corr −0.625）、+10.67%（corr −0.642）——**全部是 size 本身**。
6. 与第 9/10/11 条互相印证：无 size 的净额天花板一直是 **+4~5%** 量级，本次是把"目标函数可能写错了"
   这个最后的借口也排除了。

## 二、方法（为什么这次的目标函数是对的）

上一轮（第 9 条）的致命伤：目标函数在"20 桶**去均值**后的面板"上评分，而**平台是按原始因子值排序选股**的，
那个中性化面板不是平台看到的东西；GP 因此学会"只让残差好看"——残差线性相关 ≈0、秩相关 +0.51。

本次 `--objective aligned_net_sizecap`（`scripts/alphaprobe_gp_tushare.py`）：

- **在原始面板上算净额**（= 平台真实口径），不做任何中性化变换；
- 对**原始面板**加硬约束 `|corr_size| ≤ 0.30`（`--aligned-size-corr-cap`）；
- 不可行个体压到 −10 分以下、并按"离门槛还差多少"排序 ⇒ 保证 GP 有梯度爬向可行区（否则会退化成随机游走）；
- `corr_size` = 因子与 log(total_mv) 的逐日 Spearman 均值（与第 8/10 条同一口径，对极值免疫）。

与上一轮**完全同预算**（可对照）：374 字段、pop 400 × 10 代、seed 911、cycle 10、label_offset 1、
`2021-09-07..2026-09-07`（120 信号日、5395 只）、往返成本 0.60%（单边 0.30%）。本次记录 **1111 条**。

工程备注：失败登记表版本戳陈旧（`qualitygate3` vs `qualitygate4`，第 11 条同款），
`blocked_fields` 为空、对搜索空间无影响 ⇒ 用脚本自带的审计闸 `--allow-stale-failure-registry`
（mismatch 已记入 `gp_run.json`），不篡改登记表出处。

产物：`quantlab/.quantlab/cache/research/cn_equity/reports/alphaprobe_gp_tushare/sizecap_net_s911_20261009/`
（`aligned_ic_records.json` 1111 条）；本目录 `frontier.md`、`records_with_corr.csv`。

  "删掉全部市值/股数字段后最好 20.4%→仍是隐式 size 替代"、第 10 条"`|corr_size| ≤ 0.5` 的 39 条
  没有一条月均为正"、第 9 条"+12.76% 中性化净额实为 size 下注"三处独立证据一致。

  都已各被证伪一次以上。
