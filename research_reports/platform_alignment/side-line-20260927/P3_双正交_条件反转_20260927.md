# P3：双正交 + 条件反转（本地零算力，2026-09-27）

来源：`p3_orth_cond.py`（复用 gate6 池级账本口径；基线自检 pool_net .20703 / turn .13933 / comb .39743，
与 `ab-batch-20260925` 账本一致）。19 条候选评估，峰值 RSS 0.68GB（本机内存紧张，未超 1GB）。

## 方法

**A 双正交**：把候选的截面秩对 (a) 现役池合成秩、(b) 池 + size 秩 做逐日 OLS 取残差，
得到 `orthP`（对池正交）与 `orthPS`（池+size 双正交），再看池级增量是否改善。

**B 条件反转**：20 日负偏离反转 × 条件开关（低换手 / 深回撤 20 日 / 深回撤 60 日 / 双窗口回撤 / 叠加 / 硬阈值）。

## 结论

1. **双正交按设计生效，但不产生池级增益**：相关性确实被打下来（maxret20 corrMax 0.44→0.24、
   nb20xT5 0.41→0.25、sizeNegLog 1.00→0.01），但 s_i 同步掉得更多（.0304→.0200、.0439→.0297），
   Δnet 全部没有改善（−.015→−.022 / −.017→−.013）。**与被现役席共享的那部分信息，就是这些候选有用的那部分**；
   sizeNegLog 的 orthPS（corr 0.01）s_i 只剩 .0001 —— 去掉 size/池轴后什么都没有，第二次独立验证 GOAL.md 第 7/9 条。
2. **条件反转救不了换手**：低换手条件不降换手（同为池正交口径：Δ换手 +.131 vs 基准 +.105~.160）、s_i 从 .0191 塌到 .0039；
   回撤条件（deep20/deep60/双窗口/硬阈值）s_i 掉 30~80%、换手几乎不动（.763→.719~.754）→ Δnet 仍全负。
   根因：换手来自**持仓名单的进出**，条件开关改的是名单构成、不是进出频率。
3. **两条方法论都关闭**（本地口径，未花平台算力）。对照：SIDE-NB60T5 / SIDE-IM40 平台实测席位换手 ~0.49/0.72，
   本轮所有候选席位换手 0.085~0.76，只有 SIZE 复制品过闸（+.002Δnet、−154 分/月）。
