# size 中性化净额目标的 GP 挖掘（2026-09-24）

授权范围：用户批准的一次"size 中性化后的净额目标函数"GP 挖掘。零平台算力，全部本地。

## 一、结论（先给结论）

1. **没有找到货**。最优那条的 +13.2%（复算 +14.7%）**只存在于"20 桶去均值后的面板"上**，
   而平台是按**原始因子值**排序选股的；这条公式的**原始**版本 RankIC = +0.004、两个方向的毛超额
   都是负的（−0.6%~−1.5% / −0.9%~−1.4%），净额 −1.5%~−4.6%。**原样提交两个方向都亏。**
2. **它也不是"和 size 无关"**：原始面板与 size 秩相关 +0.17，**去均值后升到 +0.51**；
   把残差的 size **秩序**剥掉，毛超额 +19.1% → 全局剥 +4.4% / **桶内剥 −1.8%**（RankIC +0.014 ≈ 0）。
   机制：去均值用的是**均值**，被极值击穿（|value| p50=0.80、max=1.1e4）——桶均值被钉在 0，
   主体仍按 size 排序。**"+13.2% 中性化净额"本质是"比 20 桶更细一层的 size 下注"。**
3. **当席位也不合格**：`S_i ≈ 0.004`（准入线 0.035）、换手 **0.34**（准入手 0.10）、
   加第 6 席 **−270 分/月**。
4. **低换手区仍然空**：1539 条记录里净额 ≥10% 的有 259 条，其中**换手 ≤0.15 的 0 条**
   （≤0.10 也是 0 条）。最优 100 条全部是同一骨架（`MIN(OPER_DU_ROE_LYR, …)`）的平滑堆叠，
   不是"一个信号族"。
5. 附带证据：五席作为一个整体对 size 中性化后只剩 **+1.79%**（毛超额 25.96% → 7.21%），
   见 §六。

## 二、目标函数与代码位置

- 脚本：`scripts/alphaprobe_gp_tushare.py`
  - `build_size_bucket_panel(...)`：按 `total_mv` 对每个评估日等频分桶（默认 20），缺失记 −1，只依赖 size，算一次复用。
  - `size_neutralise_panel(...)`：`index_add` 求桶内均值后相减；桶内成员 <5 不动。
  - 新目标：`--objective aligned_size_neutral_net`，新参数 `--aligned-size-buckets`（默认 20）。
  - 目标定义：**在 size 桶内去均值后的面板**上，算 top-decile 年化超额 − 换手成本（往返 0.60%，单边 0.30%）。
  - ⚠️ 这里的中性化与项目正式复现口径 `ALIGNMENT_RULES` 的 N1 **同配方**（等频桶 + 桶内去均值），
    但**目标函数本身是新东西**，属于敏感性/探索口径，不写入正式结果目录，也不改规则版本。

## 四、最优族：极度自相似

最优档（+13.2% / 换手 0.34）全部是同一族的抖动版本：

```
TsMean(TsMean(Less(OPER_DU_ROE_LYR, TsMaxDiff(Ref(TsMaxDiff(Ref(
  TsMean(TS_KURT(TS_MAX(CAL_30D_PRICE_VOL_CORR,40),50),50),30),40)),30),40)),50),50)
```

- 签名 = **排他式 `MIN(oper_du_roe_lyr, ·)`** × **`TS_KURT(TS_MAX(cal_30d_price_vol_corr,40),50)`**。
- **净额 top 100 条：100/100 含 `Less(...)` 与 `oper_du_roe_lyr`；67/100 同时含 `TS_KURT` 与 `cal_30d_price_vol_corr`。**
- 即 GP 只找到**一个**方向（盈利质量指标 × 价量相关度的峰度），然后用不同程度的 `TsMean` 平滑堆叠去凑。
  没有第二个独立信号族。这本身就说明搜索空间在这个目标下很薄。

## 五·补、原始方向体检（回应"中性化后最优 +13.2%，不是一个和 size 无关的新族？"）

脚本 `scripts/sizeneut_candidate_raw_diag_20260924.py`，输出 `raw_orientation_diag.csv`（top 6）。

| 候选 | raw RankIC | raw 换手 | raw 毛超额（原向） | raw 净额（原向） | raw 净额（翻转） | raw 与 size | 中性化净额 | 中性化与 size |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| F-NET01～06 全部 | +0.003～+0.004 | 0.17～0.26 | **−0.6% ~ −1.5%** | −3.8% ~ −4.6% | −1.3% ~ −1.8% | **+0.17** | +14.5% ~ +14.7% | **+0.51 ~ +0.53** |

四条硬事实：

1. **原始方向没有 alpha，两个方向都是负的**：raw RankIC ≈ +0.004（等于 0），原向毛超额
   −0.6% ~ −1.5%、翻转后毛超额 −0.9% ~ −1.4%。**作为因子原样提交，两个方向都亏钱。**
2. **平台按原始因子值排序选股，"中性化后的面板"不是可提交对象**。+14.7% 只存在于那个
   数学变换后的面板上；这也意味着**不能把 +14.7% 当成因子收益**。
3. **它不是"和 size 无关"，恰恰相反**：原始面板与 size 轴的相关只有 **+0.17**，
   20 桶去均值之后升到 **+0.51**。也就是说这一步中性化把因子**往 size 方向推**，不是推离。
4. **中性化面板与原面板的 Rank 相关 0.46~0.51**，说明这个"变换"对这批公式不是小扰动：
   它保留了一半原值的信息，同时把截面排序改到了另一个轴上（那个轴与 size 相关 0.51）。

### 归因实验：把 size 的**秩序**剥掉，alpha 就没了

脚本 `scripts/sizeneut_panel_diag_20260924.py`（配套面板缓存 `scripts/sizeneut_panel_cache_20260924.py`，
输出 `/tmp/sizeneut_panels.npz`；`stats()` 的换手列在本脚本里写错了，**只看 IC 与毛超额**）。

| 面板 | RankIC | 毛超额 | 与 size 秩相关 | 桶内与 size 秩相关 |
| --- | ---: | ---: | ---: | ---: |
| raw（原始方向） | +0.0038 | −0.83% | −0.173 | −0.016 |
| **b20 去均值（= 本轮目标函数）** | **+0.0425** | **+19.07%** | **+0.514** | −0.016 |
| b40 去均值 | +0.0403 | +15.95% | +0.476 | +0.055 |
| b100 去均值 | +0.0356 | +12.22% | +0.401 | +0.034 |
| b20 + 全局 size 秩剥离 | +0.0268 | **+4.39%** | +0.191 | −0.129 |
| b20 + **桶内** size 秩剥离 | +0.0141 | **−1.78%** | −0.000 | −0.001 |

**机制**（为什么"中性化"没把 size 去掉）：

1. b20 去均值用的是**均值**，而该因子取值极重尾：`|value|` p50 = 0.80、p99.9 = 208、max = 1.14e4。
2. 结果：残差与 size 的 **Pearson 相关 ≈ −0.0005（=0）**，但 **Spearman（秩相关）= +0.5145**。
   即**桶均值被少数极值钉在 0，而主体仍按 size 排序**——线性/桶间那一层被切掉了，桶内的 size 秩序还在。
3. 把残差的 size **秩序**剥掉（秩空间正交化，对极值免疫）：
   - 全局剥 → 毛超额 +19.07% **→ +4.39%**
   - 桶内剥 → 毛超额 **→ −1.78%**、RankIC **+0.014**（≈ 噪声水平）
4. 更细的桶不解决问题：b100 的 RankIC 仍 +0.036、与 size 秩相关仍 +0.40，
   毛超额 +12.2% 但换手 0.63，净额只剩 +3.2%。

→ **"+13.2% 中性化净额"本质上是"比 20 桶更细一层的 size 下注"**，不是新信号族。
目标函数可被极值击穿，GP 正是从这一点上得了分。

→ 所以"最优 +13.2%（复算 +14.7%）"这个数字，**是"目标函数上的数字"，不是"能提交的因子"**。
它证明的是"在 20 桶去均值后的面板上，存在排序能力"，而那个排序能力本身与 size 相关 0.51。

（归因实验见下一节：把 size 的秩序剥掉，看这 +14.7% 还剩多少。）

## 七、判断与未证伪的空间

**结论**：size 中性化净额目标下，本地 374 字段空间内**没有可提交的候选**。
且本轮把原因定位到了目标函数本身：**"桶内按均值去中性"可被重尾极值击穿**，
GP 就在这个缺口上刷分（残差线性相关 0、秩相关 +0.51、剥掉 size 秩序后 alpha 归零）。

**尚未证伪（如果继续，按成本排序）**：
1. **修目标（本轮暴露的真问题）**：把去均值换成**对极值免疫**的中性化——桶内**中位数/秩**去中性
   （而不是均值），或在目标里显式加"原始面板 |corr_size| ≤0.3"的硬约束。
   否则 GP 会继续走"只让残差好看、原始值不可提交"的捷径。
2. **换目标**：不要用净额，用"S_i × 换手上限"或直接带 turnover penalty 的目标，看低换手区是否真无解。
3. **更细分桶**：已试 b40/b100——IC 仍 +0.036~+0.040、与 size 秩相关仍 +0.40~+0.48，
   毛超额 +12%~+16% 但换手 0.48~0.63，净额塌掉。**这条路已验证无效，不要再试。**
4. **前置过滤**：低覆盖字段应做 GP 前置（`BOND_PAYABLE` 类只有 ~1% 覆盖的字段此前污染过种群）。

**本轮不做**：不跑第二轮 GP、不改池、不上平台、不动已提交的 5 只因子（下一个低成本换人窗口是 10-01~03）。
