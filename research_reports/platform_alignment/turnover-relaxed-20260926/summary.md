# 放宽换手：5 条候选的逐月池级重算（2026-09-26，零平台算力）

脚本 `scripts/turnover_relaxed_pool_sim_20260926.py`（v2，官方 C 口径）。
内存看门狗 11GB 全程未触发（峰值 4.7GB）。

## 一、为什么必须重做

`relaxed_gp_screen_20260924` / `ab_batch_20260925` / `pending4-eval-20260926` 的池级 ΔComb
有三处口径缺口，方向都系统性偏负：

| # | 旧口径 | 官方口径（`vendor/.../references/competition_rules.md` C 节原文） |
| --- | --- | --- |
| 1 | MaxDD = 全期净值回撤（31.64%） | `MaxDD_month` 用**当月日频组合净值曲线**，每月从 1 重算 |
| 2 | 月换手 = `max(2×每次调仓换手, 0.30)` | `Turnover_month` = 当月各统一调仓日 `Σ|Δw|/2` 之和 |
| 3 | NC 全期算一次 | `Rex_ann`/`SR_ann`/`MaxDD_month` **逐月重算**，NC 逐月算 |

且 Rex/SR 的对象也不同（规则原文）：

```
Rex_ann = [(1+R_p)^(252/N) - 1] - [(1+R_b)^(252/N) - 1]     组合、基准分别复合、分别年化
SR_ann  = mean(Return_daily)/sample_std(Return_daily) × √252  用【组合日收益】，不是每日超额
rawC    = max(Rex_ann,0)/max(Turnover_month,0.3) × SR_ann × (1-1.2×MaxDD_month)
NC      = min(max(rawC/0.6, 0), 1)
```

本脚本：5 席 z 分数（重建版，已与平台逐位对齐）+ 候选第 6 席 → 逐期多头十分位 →
**等权买入持有日频净值**（组合与全 A 等权基准各一条）→ 逐月按上式算 NC → 逐月积分。

## 三、一致性校验：拿平台实测过的 AGG 对靶

AGG（`t10_size_plus_impact_aggregate`，09-24 平台 6 席池实测 **ΔComb = +148.8 分/月**）
用同一套新机器跑：

| | 平台实测 | 本机新口径 | 旧口径（全期 DD） |
| --- | ---: | ---: | ---: |
| AGG add-6th | **+148.8** | **+666（local）/ +832（uplifted）** | −3,193 |

- **符号一致**（旧口径把符号都搞反了），量级本地偏高 4.5~5.6 倍。
- 但两者不是同一个估计量：平台 +148.8 是**当月快照**的 ΔComb，本机 +666 是 **60 个月均值**；
  且平台端 AGG 的 ΔNB = +2.62%（= +403 分/月），本机**没有任何 NB 建模**。
  用平台口径反推 AGG：`ΔNA + ΔNC = 148.8 − 403 = −254`，即平台的 ΔNC ≈ −0.0185~−0.036，
  本机给的是 −0.0107 —— 同号、同量级，差 2~3 倍。
- 结论：**本机新口径可用于排序和定符号，不能当绝对分**；绝对水平必须由平台实测给出。
  这恰好把 §二 里 T2/T4 的 +482/+254（local 口径）压进了误差带。

## 四、结论与建议

1. **修正口径后，30–40% 换手档确实有两条可用候选：T2、T4**，在 local/uplifted 两种 S_i 口径下都为正；
   T1/T5 至少在一半口径下为负，建议放弃。
2. 但 §三 说明这个「为正」的幅度（+254 ~ +655）与本地误差带（±300~500）同阶。
   **要判定必须上平台。**
3. 成本：单条 6 席池实测约 **4 算力**（09-24 批次实测价），T2+T4 = **8 算力**，余额 1654.12，
   其中 46 在 09-30 到期。
4. 未建模项里，**NB（权重 0.35）是唯一可能大幅正向的**：平台端 AGG 的 ΔNB = +2.62%（+403 分/月），
   说明「加一席会稀释 NB」的旧假设是错的。

### 6.4 机制：为什么"换手放宽"这条路不成立

1. **跨过 0.30 地板**：2 调仓月基线 T=0.268（在地板下，无惩罚）；加 T2 后 T=0.35 → rawC 分母惩罚 ×0.857，
   3 调仓月 0.402→0.525（×0.766）。换手项单独就是 −14%~−23%。
2. **Rex 变差**：毛超额 −1.74pp、净 −2.37pp；月度超额均值/中位同步下降，负额月数没有改善。
3. **池级 IC 被稀释**：`P(IC>0.02)` 70.83%→63.87%、RankIC 0.0919→0.0893 —— 这席不是"高 IC 补强"，
   而是降低池的 IC 一致性（本地的 `s_i_rank` 0.050 只反映它自己的单因子 IC，不等于池级 IC 改善）。
4. **Sharpe / 全期 MaxDD 改善几乎不换分**：官方 C 的 MaxDD 用**当月**日频回撤（量级远小于全期 31.6%），
   全期 DD 从 31.64% 降到 26.28% 在月频 C 里基本不产生分数；Sharpe 的 +8.1% 是唯一的正项，
   抵不过换手与 Rex 两项。
5. 与 **09-24 AGG 对靶同向**：AGG 本地新机器 +666，平台可归因 A+C ≈ −254 —— 本地逐月机器
   **系统性高估**候选边际，本轮再次验证，且这次连符号都错。

### 6.5 结论与建议

1. **T2、T4 都不进池**（平台端均为负，T4 更差）："放宽换手档有可用候选"这条假设按证伪处理；
   失败登记表新增两条（第 13、14 条）。
2. **两条的失败机制相同、程度不同**：换手从 13.39% 抬到 17.50%（T2）/ 19.20%（T4）后，
   月换手 0.268（地板下）→ 0.35 / 0.403（地板上），rawC 分母惩罚 ×0.857 / ×0.686；
   T2 还有池级 IC 胜率 −7pp，T4 则是 Sharpe、MaxDD 双双退到基线之下。
   **T4 的月度超额与基线几乎相同（1.218% vs 1.240%）→ 它损失的全部来自换手，不是信号质量。**
3. **方法学修正（已验证两次）**：本地候选边际评估必须同时给「池级 IC 代理」
   （`RankIC×IC_IR×P(IC>0.02)`）与「加席后是否跨过 0.30 换手地板」两项；
   只看候选自己的 `s_i_rank` + 逐月 C 会给出反号结论（T2 +482 vs 实测 ≈ −2,330；T4 +254 vs ≈ −4,960）。
4. **30–40% 换手档整档关闭**；换手约束回到 ≤30%/次，即 5 席池的 13.4% 附近最多再加 1 席低换手因子。
5. 真正的约束回到 `GOAL.md` 的 A/NB 主线：A 分项已饱和（本次两条的池级 A 项分别 −270 / −38 分/月），
   NB 需要样本外 IC 样本积累，**把换手从 13% 抬到 17-19% 只会同时打坏 Rex 与 C 分母**。

### 6.7 口径更正（2026-09-26 深夜，零算力）

§6.3 的 A 侧「池级 IC 代理」（`RankIC × IC_IR × P(IC>0.02)`）**不是平台 A 口径**：
平台 A 是各席位 `s_i = |RankIC| × IR(RankIC 序列) × win(对齐硬计数)` 的算术平均。
因此 **T2/T4 的 ΔNA（−0.031 / −0.0043）是启发式，不是平台量，T2/T4 的 A 侧实际未测**；
两条"不进池"的结论仍由实测支撑（净额 −2.37pp / −1.44pp、换手 +4.11pp / +5.81pp）。
同批审查还发现 09-24 桥表把**候选 s_i 低估 37%**、把池 `raw_a` 用成本机重建口径（0.01912 vs 平台 0.025893），
修正后「加第 6 席」的边际回到 **+0.7~+1.0 千分/月**。
详见 `research_reports/platform_alignment/a-basis-correction-20260926/summary.md`。
