## 二、核心结论（决策级）

1. **净额对周期几乎不敏感，真正随周期变化的是 A 与 DD。** 六档实测：换手/次单调降 13.39 → 10.04 → 9.06 → 8.01 → 6.87 → **5.55%**，
   毛超额单调升 22.32 → **24.71%**，成本单调升 2.02 → **4.20%**，两条线在 **c5 交叉 ⇒ 净额见顶 21.35%**，
   c4~c6 只差 **0.3pp 以内**。而 **DD 单调恶化并在 c2 跳变**：31.64 → 36.24 → 42.05 → 41.82 → 44.23 → **51.10%**。
2. **⚠️ SR 与 DD 反向，不能拿 SR 选周期。** c2 的 SR **1.1591 全场最高**，但 DD **51.10% 也最差**；
   `(1−1.2·DD)` 项从 0.620 掉到 c2 的 **0.387**。此前"短周期靠 SR/净额就能赢"的直觉是错的。
3. **`s_i`（A 段）随周期单调恶化，且过 c4 后加速**：c6 .702 → c5 .708 → c4 .588 → c3 .460 → c2 **.330**，
   折算 **ΔA = −849 / −831 / −1,175 / −1,539 / −1,909 分/月**（c4 以下每降一格多贴 ~360~370）。
4. **B 段点亮率是 EV 的主导项。** `den_b ≥ 4` 的历史点亮率：cycle 1~4 = **50/58 = 86%**、cycle 5 = 76/130 = 58%、
   cycle 6 = 1/3（n=3）、cycle 7~10 = **0/113**。一个桶的差别（86% vs 33%）≈ **8,000 分/月**，
   远大于 A 与 C 的全部差價 ⇒ **"首选 cycle 6"（第一轮结论）被第二轮推翻**。
5. **定案：建池周期 = cycle 4。** `EV = ΔA + ΔC + p_B × 15,400`：

   | 重建形态 | ΔA | ΔC（3T 口径） | ΔC（k·T 口径） | p_B | EV（3T） | EV（k·T） |
   |---|---:|---:|---:|---:|---:|---:|
   | **cycle 4** | −1,175 | 0 | −6,968 | **86%** | **+12,069** | **+5,101** |
   | cycle 3 | −1,539 | 0 | −9,396 | 86% | +11,705 | +2,309 |
   | cycle 2 | −1,909 | 0 | −12,140 | 86% | +11,335 | −805 |
   | cycle 5 | −831 | 0 | −5,930 | 58% | +8,101 | +2,171 |
   | cycle 6 | −849 | 0 | −2,286 | 33%（n=3） | +4,233 | +1,947 |

   **但只能当排序、不能当点估计**：① p_B 的分母是别人的池（选择偏差——敢建短周期池的人本就是为赚 B）；
   ② 15,400 是 **NB 满分**的月值，点亮后能拿多少取决于分档；③ C 的两种口径差 3~12 倍，真值要等 10-31 抄 live `rawC`/rc。
6. **CAL 储备批把"高 s_i = 高换手"的墙再钉一次。** 已测新族 (s_i, 换手%/次) 全部落在 **(.043 ~ .061, 27 ~ 88)** 区间；
   `CT-COMP-ACTIVITY` 拿到新候选第 2 高的 s_i .0586（仅次 TOPMIX .0610），但它与 `CT-VOL-STD10`（47.04%/次）一样过不了池级换手关
   ——**composition 四线在短周期（重建）池上只会更严**（cycle 5 ⇒ 月换手再翻倍）。

## 四、方法论沉淀

1. **成本模型已闭合**：`成本 = 换手/次 × 0.30% × (252/cycle) × 2`（买卖各计一次），五条复算与平台报值**逐条一致**
   （2.53 / 2.74 / 3.03 / 3.46 / 4.20%）⇒ 换周期类候选可以**零算力外推**成本，只有 A 与 DD 必须实测。
2. **B 段点亮率是"桶"属性、不是连续量**：`cycle ≤ 4` 一整桶都是 86%，`cycle ≥ 7` 一整桶是 0 ⇒
   在桶内挑最优（本次结果 = c4），跨桶跳变才是真正的杠杆。这也说明**重建池不必"越短越好"**。
3. **DD 是要在池级单独盯的量**：它既能反转 SR 的排序（c2），也是 `rawC` 里唯一带 1.2 倍惩罚的项。
   以后任何池级形态比较，DD 必须与净额、SR 并列上报。
4. **`factor_result <run_id>` 是幂等运维的核心**：本次 c3 的 15s 读超时**服务端其实已启动**
   （重试返回 409「工作流已在运行中」），用免费 `factor_result` 取回即可，**绝不重跑**；
   判别"到底启没启动"的字段是 `factor_info.last_run_id`（c3 有值、c2 为 null ⇒ c2 才需要 `--retry-failed`）。
5. **临期余额必须看 `nextExpireAt`，不能沿用晨读**：平台按 **FIFO** 从最早到期的礼包扣，
   10-07 那次扣费直接把 23:16:43 那档 2.0 吃掉，晨读里记的"临期 2.0 @ 23:16"当场作废，实际剩余是 **8.0 @ 23:59:59**。
6. **计费分档在 120s 边界上很脆**：同一支池子 c5/c6/c4 = 115.0 / 116.3 / 115.4s（4.0 档），
   c3/c2 = **121.7 / 145.4s**（6.0 档）⇒ 预估池级成本应按 6.0 保守报，4.0 是运气不是常态。
